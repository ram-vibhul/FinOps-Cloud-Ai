Security

How CloudCostRadar protects your data and your cloud accounts.

Access to your clouds

  • Read-only roles that you create and can inspect; CloudCostRadar publishes the exact permissions it asks for.
  • AWS access uses a role with an external id unique to your connection; no long-lived access keys.
  • Automatic fixes are off by default. They need a separate role that you create, owner approval for each change, and a set of safety checks before anything runs.

Your data

  • Each organisation's data is isolated in the database with row-level security, not only in application code.
  • Secrets you give CloudCostRadar (service principal secrets, webhook addresses, keys) are encrypted at rest, and keys can be rotated.
  • You choose how long data is kept; older data is deleted automatically. You can export your data or delete your organisation at any time.

Accounts and sign-in

  • Single sign-on with OpenID Connect, enforced for your verified domains if you wish, and user provisioning with SCIM.
  • Roles, custom roles scoped to teams or accounts, temporary elevated access with a reason and an expiry.
  • An audit log of who changed what, which you can export.

How we build it

  • Release images are signed, with a software bill of materials and build provenance.
  • Open-source components are checked for licences that allow commercial use.

To report a security problem, see Support. Contact addresses are being set up.
